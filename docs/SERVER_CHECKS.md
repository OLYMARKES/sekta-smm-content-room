# Серверная приёмка

Проверки запускаются только по явной команде пользователя. Mac не используется для тестов, браузеров, сборок или установки проверочных зависимостей.

## Как устроено

Workflow [Server acceptance](../.github/workflows/server-checks.yml) использует одноразовые runner GitHub Actions на Ubuntu. Сначала выполняются регрессионные тесты источников, правок медиатеки и `workspace-safety`: URL, структура сетки, отказ записи и конфликт вкладок. Затем Chromium и WebKit проверяют приложение с настоящим каталогом на отдельном HTTP-origin с путём `/sekta-smm-content-room/`.

Браузерные сценарии охватывают навигацию и типографику, черновики и JSON, конфликт вкладок, отказ хранилища, пустую песочницу, имена и `top`, размер PNG, сохранность начатой сцены, CORS, отмену перехода к превью, мобильную ширину и клавиатуру. Добавлены сценарии CSP, логотипа, недоступного хранилища типографики и отказа сохранения сетки. Запросы к localhost перехватываются; при правках и перезагрузке ожидается отсутствие POST. Google Fonts в изолированном прогоне отключены, поэтому он не подтверждает доступность всех внешних шрифтов.

Проверочные пакеты устанавливаются в временный каталог runner. Приложение остаётся статическим и не получает npm-зависимостей или сборки. Скриншоты и результаты сохраняются как артефакты Actions на 3 дня, не в Git.

Запуски — вручную через Actions → Server acceptance → Run workflow и только после разрешения. Автоматического запуска при push нет. Новые сценарии в ветке ревью ещё не запускались; зелёная приёмка PR #1 не распространяется на последующие изменения.

## После публикации

Ручной запуск с параметром `check_live: true` повторяет приёмку и дополнительно читает опубликованный сайт. SHA-256 HTML, CSS и изменённых скриптов должен совпасть с checkout запуска. Затем оба браузера открывают опубликованную страницу и проверяют запуск конструктора. Запись в локальный сервис заблокирована; рабочие черновики пользователей не затрагиваются.

Зелёный результат относится к конкретному SHA. Он не подтверждает права публикации медиа, доступность всех оригиналов, работу отсутствующего сервиса или полное визуальное совпадение всех гарнитур. Эти ограничения остаются в [разборе проекта](PROJECT_REVIEW.md).
