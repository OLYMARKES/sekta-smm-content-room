# Черновики и исходники

Изменения от 4 сентября 2026 года поверх вечерней версии `86b5209`. Приёмка выполняется на сервере; результаты и проверенные SHA — в [PR #1](https://github.com/OLYMARKES/sekta-smm-content-room/pull/1). [Устройство проверок](SERVER_CHECKS.md).

## Черновик обложки

Основной конструктор использует новый ключ `sekta-cover-builder-draft-v1` в `localStorage`. Ключи песочницы, типографики и архивного монтажа не изменены.

Сохраняются тема, цель, аккаунт, тон, хук, подстрочник, выбранное фото, оформление, кадрирование, шрифт из примерочной и тексты сценария с ID иллюстраций. Фильтры и случайная подборка идей не являются частью проекта.

В следующей ветке ревью добавлена защита ручного текста: новая идея, новый концепт, смена цели и обновление сценария требуют подтверждения, если текст правили вручную. Отмена сохраняет сценарий, а при смене цели возвращает прежнее значение. Необязательное поле `scriptEdited` сохраняет этот признак; старые JSON без поля считаются отредактированными. Отказ буфера обмена теперь показывается как ошибка, а не как успешное копирование. Эти изменения ещё не проходили серверную приёмку.

- Автосохранение с задержкой 300 мс после изменения; при уходе со страницы выполняется попытка записать оставшиеся изменения.
- Кнопка «Сохранить черновик» позволяет повторить неудавшуюся запись.
- Некорректное сохранённое значение не заменяется стартовым состоянием автоматически. Автосохранение останавливается, пока пользователь явно не согласится на замену.
- При замеченном изменении из другой вкладки автосохранение приостанавливается. Это защита от обычной перезаписи, не транзакционная синхронизация: одновременные записи в `localStorage` не имеют серверной блокировки.
- Если фото отсутствует или закрыто для публикации в новом каталоге, ID и тексты сохраняются; вместо случайной замены показывается предупреждение. Для PNG нужно выбрать доступное фото.
- При отказе хранилища интерфейс предлагает JSON-копию. Браузерное предупреждение при закрытии — дополнительная мера; оно не гарантируется при принудительном завершении приложения.

«Экспорт JSON» сохраняет текущий редактор в формате `schema: sekta-cover-draft`, `version: 1`. «Открыть JSON» проверяет формат и запрашивает согласие перед заменой. Поддерживаются файлы до 2 МБ и до 30 слайдов, текстовые поля до 100 000 символов. Неизвестные версии и неподдерживаемые параметры отклоняются без намеренного изменения открытого проекта. Тексты вставляются как текст, не исполняемый HTML.

В JSON нет бинарных изображений, ссылок на исходники и паролей. Для переноса нужен тот же каталог с теми же ID. Тексты могут содержать рабочие материалы — не коммитьте личные резервные копии в публичный репозиторий.

## Источники изображений

[`media-source.js`](../media-source.js) читает существующие поля записи каталога. Новые пути, Drive ID и адреса сервисов не угадываются.

| Приоритет PNG | Поле | Требование |
| --- | --- | --- |
| 1 | `exportImage` | Подготовленная экспортная копия изображения |
| 2 | `originalResolution.remoteUrl` | Прямая ссылка на изображение-оригинал |
| 3 | `originalUrl` | Резервная прямая ссылка на оригинал |
| 4 | `thumb` | Превью, только с подтверждением пользователя |

Разрешены HTTP(S)-ссылки без логина и пароля в URL, в том числе относительные пути от корня приложения. Уникальные ссылки пробуются по очереди; на каждую отводится до 15 секунд. При отказе всех исходников переход к превью требует отдельного подтверждения. Отмена не запускает загрузку превью для PNG.

Внешний источник должен отдавать изображение, а не страницу просмотра/входа, и разрешать его использование в Canvas через CORS. Куки и авторизация к удалённому хранилищу этим механизмом не добавляются. Защищённым оригиналам нужен отдельно согласованный способ выдачи; секретные или подписанные приватные URL нельзя складывать в публичный каталог.

После экспорта показываются тип источника и фактически загруженные размеры. Если кадр пришлось увеличить для заполнения холста, выводится предупреждение об ограниченной детализации. Это проверка размеров, а не оценка резкости или качества фотографии.

Сцена фиксируется перед асинхронной загрузкой: изменения текста и оформления во время ожидания не смешиваются с уже начатым экспортом. Песочница использует превью 540 × 675; она не заменяет финальный PNG.

Архивный `carousel-studio.js` не подключается к этому механизму автоматически. При возвращении монтажа его экспорт нужно адаптировать отдельно.

Снимок от 3 сентября содержит 524 прямые ссылки на `storage.vigbo.tech` и отдельную карту Drive для ещё 996 материалов. Пересечений между этими группами нет; у оставшихся 930 источники не указаны. Поле `originalResolution.status` само по себе не учитывает карту Drive.

Карта [`data/drive-originals.js`](../data/drive-originals.js) используется медиатекой для кнопки скачивания оригинала. Drive-ссылка для скачивания не подставляется в Canvas: доступный человеку файл не обязательно доступен браузерному изображению с CORS. Для качественного PNG этим материалам нужна прямая экспортная копия или оригинал с подходящими заголовками. Наличие 524 прямых ссылок также не подтверждает их доступность, формат или разрешение.

**Остающийся блокер:** согласовать публичный доступ, проверить существующие источники на сервере и заполнить недостающие связи. Эта правка сохраняет вечерний каталог и карту Drive без изменений; новых медиафайлов не публикует.

## Приёмка на сервере

Выполнять только после явной команды пользователя, на изолированном серверном стенде с отдельным origin и тестовыми данными. Не использовать рабочий браузерный черновик для проверок ошибок и конфликтов.

Автоматические регрессии выбора источника: [`tests/media-source.test.cjs`](../tests/media-source.test.cjs). Используют встроенный `node:test`, подменяют загрузку изображений и не выполняют сетевых запросов. Это не проверка настоящего CORS, декодирования изображений или DOM. Команда для согласованного сервера: `node --test tests/media-source.test.cjs`. Дополнительно [`tests/release-smoke.cjs`](../tests/release-smoke.cjs) проверяет браузерные сценарии, включая CORS и PNG.

Браузерные сценарии:

1. Изменить все поля, кадрирование и ручные тексты сценария. Дождаться статуса сохранения, перезагрузить: содержимое и иллюстрации восстановлены. Повторить с пустым хуком и многострочным текстом.
2. Сразу после ввода уйти со страницы; затем вернуться. Отдельно проверить отказ записи и переполнение хранилища: нет ложного «сохранено», JSON остаётся доступен в пределах лимита.
3. Экспортировать JSON и открыть в другом чистом клиенте с тем же каталогом. Проверить отмену импорта, повреждённый JSON, неизвестную версию, слишком большой файл и HTML в текстовых полях.
4. Открыть две вкладки, изменить черновик в первой. Во второй автоматическая запись приостановлена; ручная замена требует подтверждения, отмена сохраняет чужую версию.
5. Удалить выбранное фото из тестового каталога или пометить `not-public`, затем загрузить сохранённый черновик: нет случайной подстановки фото, ID и тексты доступны для экспорта.
6. Проверить по очереди доступную экспортную копию, только оригинал, только превью, ошибку оригинала и CORS. Отказ от превью не скачивает PNG. Для маленького изображения показано предупреждение об увеличении.
7. Во время медленной загрузки исходника изменить фото, хук и кадрирование: начатый PNG сохраняет прежнюю сцену. Следующий экспорт использует новые настройки.
8. Проверить подписи, клавиатуру, файловый диалог и новый ряд кнопок на узком экране.

Перечень выше задаёт границы приёмки, а не обещает проверку всех внешних источников и шрифтов. Выполненные сценарии и ограничения указываются рядом с результатом конкретного запуска.
