# Сохранение имён и отметок

Исправление подготовлено для PR #1. Runtime-проверки не выполнялись.

## Что меняется

Раньше успешный ответ локального сервиса удалял браузерную копию. Если опубликованный каталог ещё не обновился, после перезагрузки возвращались старые данные. Сохранение имён могло удалить и ожидающую отправки отметку «в топ».

Теперь [`media-overrides.js`](../media-overrides.js) сохраняет правку в браузере до запроса. Только после успешной записи интерфейс меняет имена или отметку. При отказе хранилища имена остаются в открытой форме, а отметка не переключается; показывается ошибка.

- Успешный ответ сервиса снимает ожидание отправки, но не удаляет локальные значения. Перезагрузка со старым каталогом использует браузерную копию.
- Имена и `top` имеют отдельный список ожидающих полей. Сохранение одного не удаляет другое; уже подтверждённое поле не отправляется повторно из-за изменения соседнего.
- Запросы из этой вкладки идут по очереди, включая стартовый повтор отправки. Ответ на старую версию не подтверждает более новую правку. Ошибка не блокирует последующие попытки.
- При замеченном изменении хранилища другой вкладкой запись и новая отправка останавливаются. Уже выполняющийся запрос отменить этим сравнением нельзя.
- Обновление статуса после запроса и переключение «в топ» не пересоздают форму с ещё не сохранёнными именами.
- «Сохранено в браузере» и «сервис принял правки» — разные состояния. Второе не означает, что общий опубликованный каталог уже обновлён.

## Совместимость и границы

Ключ `sekta-media-people-overrides-v1` не меняется. Старые записи с `pending: true` читаются без миграции: их доступные поля считаются ожидающими. Новое необязательное поле `pendingFields` уточняет, какие значения ещё нужно отправить. Повреждённый JSON не заменяется пустым объектом; другие записи и дополнительные поля сохраняются.

Адрес, формат HTTP-запроса и проверка ответа существующего сервиса не меняются. Сам сервис в репозитории отсутствует. Его задержки, таймауты и запись из других клиентов не контролируются этой очередью: для строгого порядка на сервере нужны версии записей. Повтор после ошибки выполняется при следующей загрузке страницы или новом изменении материала; постоянного фонового опроса нет.

Сравнение `localStorage` не является атомарной блокировкой двух вкладок. Локальные значения имеют приоритет над опубликованным каталогом и автоматически не удаляются даже после совпадения с ним. Поэтому более поздняя правка другого человека может быть скрыта локальной копией. Согласование версий и осознанный сброс локальных значений — отдельная задача общего API; автоматически стирать данные ради этого исправления нельзя.

## Приёмка на сервере

Только по явной команде пользователя, с отдельным origin и тестовым хранилищем. На компьютере пользователя не запускать.

[`tests/media-overrides.test.cjs`](../tests/media-overrides.test.cjs) содержит 14 регрессионных сценариев с хранилищем в памяти и подменённым транспортом. Команда для согласованного сервера: `node --test tests/media-overrides.test.cjs`. Тесты не проверяют реальный сервис или интерфейс и здесь не запускались.

Браузерная приёмка:

1. Изменить имена и `top`, получить ответ тестового сервиса, перезагрузить со старым каталогом: оба значения остались.
2. Отключить сервис: локальная запись сохраняется сразу, сообщение не обещает общую синхронизацию. После перезагрузки с доступным сервисом отправить ожидающие значения.
3. Задержать ответ, быстро переключить `top` и изменить имена: последний локальный выбор не удалён старым ответом, итоговый запрос содержит актуальные ожидающие поля.
4. Подменить запись хранилища ошибкой: звезда не меняется, введённые имена не исчезают, форма остаётся доступной для повторного сохранения.
5. Изменить хранилище во второй вкладке, затем сохранить в первой: чужая копия не перезаписана. Отдельно повторить во время ожидающего ответа сервиса.
6. Начать вводить новые имена и нажать «в топ»: текст остаётся в форме. Получить ответ старого запроса во время нового ввода: форму не заменяет сохранённая версия.
7. Открыть карточку повторно: виден статус локальной записи. Проверить пустой список имён, `top: false`, повреждённый JSON и старый формат без `pendingFields`.
