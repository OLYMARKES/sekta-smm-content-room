# Командная Content Room

Этот каталог содержит командную Content Room на `sekta2`: [content.sekta2.ru](https://content.sekta2.ru). Она использует Next.js 16, Better Auth и PostgreSQL. Сайт на GitHub Pages продолжает работать отдельно; данные в браузерах коллег не переносятся автоматически и не удаляются.

## Возможности

- Вход через Google или почту с паролем. Для пароля требуется подтверждение почты; восстановление отправляется через SMTP.
- Регистрация и доступ к материалам только по адресу, заранее внесённому в команду администратором. Почта должна быть подтверждена. Первый владелец задаётся `TEAM_OWNER_EMAIL`.
- Роли: владелец и администратор управляют доступом и этапами; редактор собирает серии; ревьюер согласует; просмотр не меняет данные.
- Общие серии в PostgreSQL. Сохранение требует актуального номера версии. При конфликте сервер возвращает `409` и не перезаписывает работу коллеги.
- История каждой версии, экспорт старой версии в JSON и восстановление как нового черновика. Изменение содержания после отправки на ревью снимает согласование.
- Локальный конструктор доступен по `/editor/postbuilder.html`. Кнопка «Сохранить в команде» отправляет именно текущую серию. После первого сохранения общий черновик автоматически обновляется через 1,5 секунды бездействия. При ревью и согласовании содержимое сохраняется вручную с подтверждением возврата в черновики.

- Комментарии к серии и слайдам доступны редакторам и ревьюерам. Упоминания видны в обсуждении. Уведомления пока не отправляются.
- Фото команды хранятся в PostgreSQL вместе с миниатюрами, тегами и сведениями об источнике. JPG, PNG и WebP до 5 МБ доступны для выбора и экспорта через авторизованный API.
- Email и Threads доступны из командной комнаты. Общие черновики можно переносить через JSON. Email выгружается в HTML, Threads в TXT. Тему и служебный подвал письма нужно проверить в Mindbox перед отправкой.

Этап «Опубликовано» остаётся ручной отметкой команды.

## Работа команды

Владелец входит на [content.sekta2.ru/sign-in](https://content.sekta2.ru/sign-in) и добавляет коллег в разделе «Команда» по их адресам электронной почты. Коллега задаёт пароль с подтверждением почты либо входит через Google. Пока Google OAuth находится в режиме тестирования, для Google входа адрес коллеги также должен быть добавлен в список тестовых пользователей Google Cloud; почтовый вход этого ограничения не имеет. Без приглашения материалы и API закрыты. Пароль можно восстановить письмом. Для совместного редактирования откройте серию в командной комнате, нажмите «Конструктор поста», затем «Сохранить в команде». При конфликте версий сервер не перезаписывает работу другого редактора.

## Развёртывание на `sekta2`

- Исходники размещаются в `/opt/sekta-content-room-source`; секреты — в `team/.env` с правами `0600`. Публичный адрес задаётся `BETTER_AUTH_URL=https://content.sekta2.ru`. Не сохраняйте `.env` в Git.
- `swarm.yml` подключает приложение к действующему Traefik через `main_net` и к PostgreSQL через закрытую overlay сеть. База не публикует порт наружу. Том БД — `content-room_content-room-pg`. Сервис закреплён за узлом `sekta2`.
- SMTP читает Docker secret `sektabot-stage_v1_smtp_server` через `SMTP_SERVER_FILE`. Этот secret должен существовать на сервере. Для другого окружения можно задать `SMTP_SERVER` или `SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASSWORD`.
- Google OAuth требует Web client с origin `https://content.sekta2.ru` и redirect URI `https://content.sekta2.ru/api/auth/callback/google`. ID и secret хранятся только в серверном `.env`. Без них остаётся почтовый вход.
- Перед первым запуском и после обновления схемы выполните на сервере миграции из `compose.yml`: `docker compose --profile maintenance run --rm migrate` из каталога `team`. Соберите образ из корня исходников командой `docker build -f team/Dockerfile -t sekta-content-room:<тег> .`, задайте `CONTENT_ROOM_IMAGE_TAG=<тег>` в серверном `.env`, затем выполните `python3 scripts/deploy-stack.py` из каталога `team`. Скрипт создаёт временный файл конфигурации с правами `0600` и удаляет его после `docker stack deploy`.
- `team/scripts/backup-db.py` создаёт закрытый архив PostgreSQL в `/opt/content-room-backups`. Флаг `--verify-restore` полностью восстанавливает архив во временную БД, сверяет основные таблицы и удаляет временную БД. Установлен ежедневный запуск через `team/ops/content-room-backup.cron` в 03:15 по времени сервера. Для защиты от потери всего сервера копии дополнительно следует отправлять во внешнее хранилище; текущий cron хранит их на `sekta2`.

`compose.yml` подходит для локального loopback запуска; публичный сервер использует `swarm.yml`. Проверки и сборки по правилам этого проекта выполняются только на сервере и по явной команде пользователя, не на Mac.

## Перенос из GitHub Pages

Локальные данные в браузере на `olymarkes.github.io` нельзя прочитать с нового домена. Каждый редактор сначала выгружает нужные серии кнопкой «Экспорт JSON» в конструкторе или скачивает общую копию для сохранности. Затем в командной комнате выбирает «Импортировать JSON» для каждой отдельной серии. Импорт создаёт новую общую запись и оставляет локальный файл без изменений. Общая копия всего workspace не принимается за отдельную серию.

Первую общую версию создаёт кнопка «Сохранить в команде». Уже открытый общий черновик автосохраняется на сервере. Коллеги видят новую версию при повторном открытии серии. При конфликте сохраните JSON, обновите общую серию и внесите нужные изменения в актуальную версию.

## Серверная приёмка

- Без приглашения подтверждённый пользователь не видит `/team`, `/editor/*.html` и API материалов.
- Приглашённый редактор входит обоими способами, импортирует JSON, открывает серию, меняет бриф и сохраняет в команде.
- В двух сессиях вторая запись по устаревшей версии получает `409`; первая версия и история остаются целыми.
- Редактор отправляет на ревью; ревьюер согласует. Правка согласованной серии возвращает её в черновик. Опубликованная серия не перезаписывается.
- Администратор убирает доступ; старая сессия больше не читает API материалов.
- Историческая версия скачивается и восстанавливается как новый черновик без удаления текущей из истории.
- Обновлённый конструктор экспортирует PNG, ZIP и JSON. В ZIP одна и многослайдовая серии содержат PNG в правильном порядке, бриф и подпись.
- Выбор слайда в согласованной серии сохраняет этап. Редактирование общего черновика запускает отложенное сохранение. При конфликте локальный черновик доступен для экспорта.
- Ревьюер пишет комментарии к серии и слайду, пользователь с ролью просмотра читает обсуждение. Фото видно второму участнику, гость получает отказ на оригинал и миниатюру.
- Команда сохраняет и повторно открывает Email и Threads. Выгруженный HTML проверяется в Mindbox на реальном шаблоне. Эти сценарии требуют отдельной приёмки.

Базовые сценарии предыдущей версии проверялись в изолированной серверной БД скриптом `team/scripts/acceptance-server.mjs`: приглашения, подтверждение почты, парольный вход, роли, CRUD серий, конфликт версий, ревью, восстановление истории и отзыв сессии. Google вход владельца и HTTPS также проверены на рабочем адресе. Статический экспорт PNG и JSON из прежней комнаты остаётся отдельным сценарием.

### Threads Desk

Банк тем перенесён из [Threads Desk](https://github.com/KateAndik/sekta-threads-constructor/tree/eaf4eade4988758665f49c60cf059b4813171117). В календаре показываются общие черновики с датой, аккаунтом и слотом. Перенесены четыре аккаунта, недельная сетка и три слота на день. Записи из локальных браузеров участников хранятся на старом домене и требуют отдельного импорта.
