# Командная Content Room

Этот каталог содержит серверный контур для размещения на `sekta2`. Он использует Next.js 16, Better Auth и PostgreSQL. Текущий сайт на GitHub Pages продолжает работать отдельно: PR не переносит и не удаляет пользовательские данные из браузеров.

## Возможности

- Вход через Google или почту с паролем. Для пароля требуется подтверждение почты; восстановление отправляется через SMTP.
- Регистрация и доступ к материалам только по адресу, заранее внесённому в команду администратором. Почта должна быть подтверждена. Первый владелец задаётся `TEAM_OWNER_EMAIL`.
- Роли: владелец и администратор управляют доступом и этапами; редактор собирает серии; ревьюер согласует; просмотр не меняет данные.
- Общие серии в PostgreSQL. Сохранение требует актуального номера версии. При конфликте сервер возвращает `409` и не перезаписывает работу коллеги.
- История каждой версии, экспорт старой версии в JSON и восстановление как нового черновика. Изменение содержания после отправки на ревью снимает согласование.
- Локальный конструктор доступен по `/editor/postbuilder.html`. Кнопка «Сохранить в команде» отправляет именно текущую серию. Локальное автосохранение и JSON-экспорт остаются отдельными способами сохранения.

Этап «Опубликовано» пока ручной. Интеграции с Instagram, общего редактирования медиатеки и автоматической синхронизации других локальных разделов здесь нет. Эти возможности требуют отдельной модели данных и прав; интерфейс их не обещает.

## Подготовка `sekta2`

1. Выберите HTTPS-домен для приложения. `content.sekta.work` в `.env.example` — пример, не утверждённый адрес.
2. Создайте на сервере `team/.env` из примера. Укажите `CONTENT_ROOM_DB_PASSWORD`, `BETTER_AUTH_SECRET` (не менее 32 случайных байт), `TEAM_OWNER_EMAIL`, SMTP и `BETTER_AUTH_URL`. Не сохраняйте секреты в Git.
3. Создайте Google OAuth Web client и укажите callback `https://<домен>/api/auth/callback/google`; заполните `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Без этих переменных Google-кнопка скрыта, а почтовый вход остаётся доступен.
4. Подключите reverse proxy с TLS к `127.0.0.1:3097`. Доступ к PostgreSQL снаружи не публикуется.
5. На сервере, после отдельного разрешения проверок, соберите контейнер и примените две миграции через одноразовый сервис `migrate` (`docker compose --profile maintenance run --rm migrate`). Он выполняет `npm run auth:migrate` для таблиц Better Auth, `npm run db:migrate` для данных команды и `npm run auth:check` для сверки схемы. Compose поднимает отдельную базу `content_room`.
6. Настройте резервную копию тома `content-room-pg` и проверьте восстановление до выдачи доступа команде. История версий внутри той же базы не заменяет независимый backup.
7. Проверьте сценарии ниже на серверном окружении; Mac пользователя для этого не использовать.

Сборка Docker происходит до запуска базы, поэтому автоматическая проверка схемы Better Auth при инициализации выключена. Миграции и явная серверная проверка схемы должны завершиться успешно до открытия приложения команде.

`compose.yml` привязывает веб-приложение только к loopback. Публикация домена и миграции не выполняются этим PR автоматически.

## Перенос из GitHub Pages

Локальные данные в браузере на `olymarkes.github.io` нельзя прочитать с нового домена. Каждый редактор сначала выгружает нужные серии кнопкой «Экспорт JSON» в конструкторе или скачивает общую копию для сохранности. Затем в командной комнате выбирает «Импортировать JSON» для каждой отдельной серии. Импорт создаёт новую общую запись и оставляет локальный файл без изменений. Общая копия всего workspace не принимается за отдельную серию.

Для уже открытой общей серии локальные правки сохраняются в браузере автоматически, но становятся видны коллегам только после «Сохранить в команде». При конфликте сохраните JSON, обновите общую серию и внесите нужные изменения в актуальную версию.

## Серверная приёмка (только по явной команде)

- Без приглашения подтверждённый пользователь не видит `/team`, `/editor/*.html` и API материалов.
- Приглашённый редактор входит обоими способами, импортирует JSON, открывает серию, меняет бриф и сохраняет в команде.
- В двух сессиях вторая запись по устаревшей версии получает `409`; первая версия и история остаются целыми.
- Редактор отправляет на ревью; ревьюер согласует. Правка согласованной серии возвращает её в черновик. Опубликованная серия не перезаписывается.
- Администратор убирает доступ; старая сессия больше не читает API материалов.
- Историческая версия скачивается и восстанавливается как новый черновик без удаления текущей из истории.
- Обновлённый конструктор по-прежнему экспортирует PNG и JSON на статическом сайте.

До такой приёмки командный контур остаётся черновиком для ревью и не должен становиться основным рабочим адресом команды.
